## Database migrations

Database schema changes are managed by Alembic. The connection is assembled
from `DB_IP`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASS`; credentials are
not stored in `alembic.ini`.

Docker Compose runs `alembic upgrade head` in the one-shot `migrate` service
before starting the API:

```bash
docker compose up -d --build
```

Useful commands:

```bash
# Show the database revision
docker compose run --rm api alembic current

# Check whether model metadata and the database schema differ
docker compose run --rm api alembic check

# Generate a migration after changing app/data/database_schema.py
docker compose run --rm api alembic revision --autogenerate -m "describe change"

# Apply pending migrations manually
docker compose run --rm api alembic upgrade head

# Roll back one revision
docker compose run --rm api alembic downgrade -1
```

Review every autogenerated migration before applying it. `alembic stamp` is
only for adopting a pre-existing schema; do not use it to initialize a new,
empty database.
